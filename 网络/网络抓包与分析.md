## 前言

在排查网络与应用问题时，常见的现象包括：接口偶发超时、连接被重置、数据库连接不稳定、TLS 握手失败、带宽异常。仅看应用日志往往无法确定问题出在哪一环，而网络数据包记录了通信双方实际发送和接收的内容。

生产环境中最常用的组合是：

- **tcpdump**：在服务器上抓包。它轻量，无需图形界面，大多数 Linux 发行版都能直接安装使用。
- **Wireshark**：在本地电脑上分析。它提供图形界面、深度协议解析和统计功能。

# 1. tcpdump 介绍

tcpdump 是一款基于命令行的网络数据包捕获与分析工具，最早由劳伦斯伯克利国家实验室开发，在类 Unix 系统中广泛使用。它可以：

- 实时捕获经过网卡的数据包，并按协议格式输出到终端；
- 按 BPF 过滤表达式精确筛选数据包；
- 将原始数据包保存为 `pcap` 文件，交给 Wireshark 等工具离线分析。

## 1.1 工作原理

tcpdump 工作原理如下：

```
   用户空间         tcpdump
                      │
                  libpcap（抓包库）
──────────────────────┼──────────────
   内核空间       BPF 过滤器（在内核中执行）
                      │  只复制匹配的包
                 网络协议栈 / 网卡驱动
                      │
                   物理网卡
```

1. **libpcap**：跨平台抓包库。tcpdump、Wireshark 和 Nmap 都依赖它或它的 Windows 版本 Npcap。
2. **BPF（Berkeley Packet Filter）**：过滤表达式会被编译成 BPF 字节码并在内核中执行。只有匹配的数据包才会复制到用户空间，这是 tcpdump 性能高的主要原因。
3. **混杂模式（Promiscuous Mode）**：默认情况下，tcpdump 会把网卡设为混杂模式，接收所有流经网卡的帧，而不仅是发给本机的帧。可以用 `-p` 关闭。
4. **抓包位置**：
   - 入方向：数据包在进入协议栈之前被捕获，因此即使之后被 iptables 丢弃，tcpdump 也能看到。
   - 出方向：数据包在即将交给网卡驱动时被捕获。

## 1.2 命令用法

tcpdump 是 macOS 和大多数 Linux 发行版默认预装的软件包，命令为 tcpdump，需要 root 权限运行。

常用参数：

| 参数              | 说明                                                         |
| ----------------- | ------------------------------------------------------------ |
| `-D`              | 列出所有可抓包的网卡接口                                     |
| `-i <iface>`      | 指定网卡，如 `eth0`；`-i any` 表示所有网卡                   |
| `-n`              | 不把 IP 解析为主机名                                         |
| `-nn`             | 既不解析主机名，也不把端口解析为服务名（推荐始终加上）       |
| `-c <N>`          | 抓到 N 个包后自动退出                                        |
| `-s <len>`        | 每个包截取的长度（snaplen），`-s 0` 表示完整抓取（新版本默认 262144 字节） |
| `-w <file>`       | 把原始数据包写入文件（pcap 格式），不在终端解析显示          |
| `-r <file>`       | 从 pcap 文件读取数据包并解析                                 |
| `-C <size>`       | 单个文件达到 size（单位为百万字节）后切换到新文件            |
| `-W <N>`          | 与 `-C` 或 `-G` 配合使用，最多保留 N 个文件并循环覆盖        |
| `-G <sec>`        | 每隔 sec 秒切换一个新文件，文件名可使用 strftime 格式        |
| `-U`              | 配合 `-w` 使用，每抓到一个包立即写出，不做缓冲（管道实时传输时必须加） |
| `-B <KiB>`        | 设置内核抓包缓冲区大小，流量大时可减少丢包                   |
| `-v / -vv / -vvv` | 输出更详细的协议信息                                         |
| `-e`              | 显示链路层头部信息（MAC 地址）                               |
| `-A`              | 以 ASCII 显示包内容，适合查看 HTTP 明文                      |
| `-X`              | 以十六进制和 ASCII 同时显示包内容（不含链路层）              |
| `-XX`             | 同 `-X`，但包含链路层头部                                    |
| `-tttt`           | 显示完整的日期和时间戳                                       |
| `-q`              | 精简输出                                                     |
| `-l`              | 行缓冲输出，便于配合 `grep` 实时过滤                         |
| `-p`              | 不开启混杂模式                                               |
| `-Z <user>`       | 抓包后以指定用户身份写文件（遇到文件权限问题时可用 `-Z root`） |

常用命令示例：

```bash
# 1. 查看可用网卡
tcpdump -D

# 2. 抓 eth0 上所有包，不做解析，只抓 100 个
tcpdump -i eth0 -nn -c 100

# 3. 抓与某台主机之间的通信
tcpdump -i eth0 -nn host 10.0.0.5

# 4. 抓某端口的流量，排除 SSH（避免自己的 SSH 会话流量干扰）
tcpdump -i any -nn 'port 8080 and not port 22'

# 5. 抓 MySQL 流量并保存到文件
tcpdump -i eth0 -nn -s 0 port 3306 -w /tmp/mysql.pcap

# 6. 实时查看 HTTP 明文内容
tcpdump -i eth0 -nn -A -s 0 'tcp port 80'

# 7. 抓 DNS 查询
tcpdump -i any -nn udp port 53

# 8. 抓 ICMP（ping）包
tcpdump -i eth0 -nn icmp

# 9. 按大小滚动保存：每个文件 100MB，最多保留 10 个，循环覆盖
tcpdump -i eth0 -nn -s 0 port 443 -C 100 -W 10 -w /data/cap/https.pcap

# 10. 按时间滚动保存：每小时一个文件
tcpdump -i eth0 -nn -G 3600 -w '/data/cap/trace_%Y%m%d_%H%M%S.pcap'

# 11. 读取 pcap 文件，并在读取时再次过滤
tcpdump -nn -r /tmp/mysql.pcap 'host 10.0.0.8'

# 12. 配合 grep 实时查找关键字（需要加 -l）
tcpdump -i eth0 -nn -l -A port 80 | grep -i 'User-Agent'
```

## 1.3 过滤表达式

过滤表达式是 tcpdump 的核心能力。它由一个或多个"原语"组成，原语之间用逻辑运算符连接。

建议把整个过滤表达式放在单引号中，避免被 shell 解析：

```bash
tcpdump -i eth0 -nn 'host 10.0.0.1 and (port 80 or port 443)'
```

限定词：

| 类型 | 关键字                                            | 示例                                                         |
| ---- | ------------------------------------------------- | ------------------------------------------------------------ |
| 类型 | `host`、`net`、`port`、`portrange`                | `host 10.0.0.1`、`net 192.168.0.0/16`、`port 80`、`portrange 8000-8100` |
| 方向 | `src`、`dst`、`src or dst`、`src and dst`         | `src host 10.0.0.1`、`dst port 443`                          |
| 协议 | `ether`、`ip`、`ip6`、`arp`、`tcp`、`udp`、`icmp` | `tcp port 3306`、`udp port 53`、`icmp`                       |

逻辑运算：

| 运算 | 写法                               |
| ---- | ---------------------------------- |
| 与   | `and` 或 `&&`                      |
| 或   | `or` 或 `\|\|`                     |
| 非   | `not` 或 `!`                       |
| 分组 | `( )`，在 shell 中需要加引号或转义 |

高级过滤：

按字节偏移与 TCP 标志位，语法格式为 `proto[offset:size]`。

TCP 标志位与数值的对应关系：`FIN=1`、`SYN=2`、`RST=4`、`PSH=8`、`ACK=16`、`URG=32`。

```bash
# 只抓 SYN 包（建立连接的第一次握手）
tcpdump -i eth0 -nn 'tcp[tcpflags] & (tcp-syn|tcp-ack) == tcp-syn'
# 抓 RST 包（连接被重置）
tcpdump -i eth0 -nn 'tcp[tcpflags] & tcp-rst != 0'
# 抓 SYN 或 FIN 包（观察连接的建立与关闭）
tcpdump -i eth0 -nn 'tcp[tcpflags] & (tcp-syn|tcp-fin) != 0'
# 等价写法：TCP 头部第 13 字节是标志位
tcpdump -i eth0 -nn 'tcp[13] & 4 != 0'     # RST
# 抓 HTTP GET 请求（TCP 载荷前 4 字节为 "GET "）
tcpdump -i eth0 -nn 'tcp port 80 and tcp[((tcp[12:1] & 0xf0) >> 2):4] = 0x47455420'
# 抓大于 1000 字节的包
tcpdump -i eth0 -nn 'greater 1000'
```

## 1.4 输出格式

示例输出：

```
14:23:01.123456 IP 192.168.1.10.54321 > 10.0.0.5.80: Flags [S], seq 1234567890, win 64240, options [mss 1460,sackOK,TS val 1 ecr 0,nop,wscale 7], length 0
14:23:01.124001 IP 10.0.0.5.80 > 192.168.1.10.54321: Flags [S.], seq 987654321, ack 1234567891, win 65160, options [...], length 0
14:23:01.124100 IP 192.168.1.10.54321 > 10.0.0.5.80: Flags [.], ack 1, win 502, length 0
14:23:01.124500 IP 192.168.1.10.54321 > 10.0.0.5.80: Flags [P.], seq 1:79, ack 1, win 502, length 78: HTTP: GET / HTTP/1.1
```

字段含义：

| 字段                 | 含义                                                        |
| -------------------- | ----------------------------------------------------------- |
| `14:23:01.123456`    | 时间戳（精确到微秒）                                        |
| `IP`                 | 网络层协议（IPv6 显示为 `IP6`）                             |
| `192.168.1.10.54321` | 源 IP 和源端口（最后一段是端口）                            |
| `>`                  | 数据流向                                                    |
| `Flags [S]`          | TCP 标志位                                                  |
| `seq` / `ack`        | 序列号 / 确认号（后续包默认显示相对值，加 `-S` 显示绝对值） |
| `win`                | 接收窗口大小                                                |
| `options`            | TCP 选项（MSS、SACK、时间戳、窗口缩放等）                   |
| `length`             | TCP 载荷长度                                                |

Flags 中各字母的含义，可以组合出现：

* `S`：SYN
* `F`：FIN
* `P`：PUSH
* `R`：RST
* `.`：ACK
* `U`：URG
* `E` / `W`：ECE / CWR（显式拥塞通知）

## 1.5 注意事项

1. **务必使用过滤条件**：在流量大的生产服务器上不加过滤地抓包，会迅速产生巨大的文件，并消耗 CPU 和磁盘 IO。

2. **注意磁盘空间**：长时间抓包一定要用 `-C` / `-W` 或 `-G` 做文件轮转，防止磁盘被写满。

3. **排除 SSH 流量**：远程登录抓包时加上 `not port 22`，否则会抓到自己 SSH 会话的流量，产生"抓包 → 输出 → 再抓包"的循环。

4. **留意丢包提示**：抓包结束时 tcpdump 会输出统计信息：

   ```
   12345 packets captured
   12400 packets received by filter
   55 packets dropped by kernel
   ```

   如果 `dropped by kernel` 不为 0，说明有丢包。可以用 `-B` 加大缓冲区、收紧过滤条件，或者写入更快的磁盘。

# 2. Wireshark

Wireshark 是一款开源免费的图形化网络协议分析器，支持 Windows、macOS 和 Linux。

它的主要特点包括：

- 能解析数千种协议，从以太网、IP、TCP 到 HTTP、TLS、MySQL、Redis、Kafka、gRPC 等；
- 提供强大的显示过滤器；
- 内置丰富的统计与可视化功能，如 TCP 流图、IO 图表、会话统计等；
- 能自动识别重传、乱序、零窗口等 TCP 异常，并在"专家信息"中汇总。

打开 pcap 文件后的应用界面如下：

* 顶部是显示过滤器输入栏，过滤符合条件的包；
* 中间是数据包列表区，每行包含时间、源和目标、协议、长度、信息内容；
* 左下是数据包详情区，按协议分层展开树形结构；
* 右下是数据包字节区，显示十六进制和 ASCII 原始数据；

![](https://article-1304941664.cos.ap-guangzhou.myqcloud.com/network/wireshark.jpg)

Wireshark 可以在本地进行抓包，也可以打开用 tcpdump 抓包生成的 pcap 文件。

## 2.1 显示过滤器

捕获过滤器（Capture Filter）作用于抓包时，不匹配的包直接丢弃，使用BPF 语法（与 tcpdump 相同）。显示过滤器（Display Filter）则用于抓包后，只控制显示哪些包，原始数据不变，是 Wireshark 专有语法。

比较运算符：

| 运算符            | 含义                                     |
| ----------------- | ---------------------------------------- |
| `==` / `eq`       | 等于                                     |
| `!=` / `ne`       | 不等于                                   |
| `>` `<` `>=` `<=` | 大小比较                                 |
| `contains`        | 包含（字符串或字节）                     |
| `matches` / `~`   | 正则匹配                                 |
| `in {}`           | 集合匹配，如 `tcp.port in {80 443 8080}` |

逻辑运算符：

`&&` / `and`、`||` / `or`、`!` / `not`，可以用括号分组。

常用过滤示例：

```
# —— 地址与端口 ——
ip.addr == 10.0.0.5                  # 源或目的 IP 为 10.0.0.5
ip.src == 10.0.0.5                   # 源 IP
ip.dst == 10.0.0.0/24                # 目的网段
tcp.port == 8080                     # 源或目的端口
tcp.dstport == 3306
udp.port == 53
tcp.port in {80 443 8080}

# —— 协议 ——
http
dns
tls
arp
icmp
mysql
!(arp || dns || icmp)                # 排除干扰协议

# —— TCP 标志与状态 ——
tcp.flags.syn == 1 && tcp.flags.ack == 0     # SYN 包（第一次握手）
tcp.flags.reset == 1                         # RST 包
tcp.flags.fin == 1                           # FIN 包
tcp.stream eq 5                              # 第 5 条 TCP 流

# —— TCP 异常分析（非常常用）——
tcp.analysis.flags                           # 所有 TCP 异常
tcp.analysis.retransmission                  # 重传
tcp.analysis.fast_retransmission             # 快速重传
tcp.analysis.duplicate_ack                   # 重复 ACK
tcp.analysis.lost_segment                    # 疑似丢包
tcp.analysis.zero_window                     # 零窗口
tcp.analysis.window_full                     # 窗口满
tcp.time_delta > 1                           # 与同一流中上一个包的间隔超过 1 秒

# —— HTTP ——
http.request                                 # 所有 HTTP 请求
http.request.method == "POST"
http.request.uri contains "/api/login"
http.host == "www.example.com"
http.response.code >= 500
http.time > 2                                # 响应耗时超过 2 秒

# —— DNS ——
dns.qry.name contains "example.com"
dns.flags.rcode != 0                         # DNS 解析失败

# —— TLS ——
tls.handshake.type == 1                      # Client Hello
tls.handshake.extensions_server_name == "api.example.com"   # 按 SNI 过滤
tls.alert_message                            # TLS 告警

# —— 内容匹配 ——
frame contains "error"
tcp.payload contains "timeout"
http.user_agent matches "(?i)curl"
```

# 3. 抓包与分析流程

对于使用服务器 tcpdump 抓包 + 本地 Wireshark 分析的场景，整体流程如下：

```
┌─────────────┐   ① 明确目标    ┌──────────────┐   ② 登录服务器
│ 问题现象     │ ─────────────▶ │ 制定抓包方案   │ ─────────────▶
└─────────────┘                └──────────────┘
                                                              │
  ┌───────────────────────────────────────────────────────────┘
  ▼
┌──────────────┐ ③ 执行 tcpdump ┌──────────────┐ ④ 复现问题后停止
│ 确认网卡/过滤  │ ─────────────▶ │ 保存 pcap 文件 │ ─────────────▶
└──────────────┘                └──────────────┘
                                                                │
  ┌─────────────────────────────────────────────────────────────┘
  ▼
┌──────────────┐ ⑤ scp/rsync/sz  ┌──────────────┐ ⑥ Wireshark 分析
│ 压缩 pcap     │ ─────────────▶  │ 本地电脑       │ ─────────────▶ 结论
└──────────────┘                 └──────────────┘
```

## 3.1 明确抓包目标

动手之前先回答以下几个问题，它们决定了过滤条件和抓包位置：

| 问题                   | 示例                                         |
| ---------------------- | -------------------------------------------- |
| 要分析哪条链路？       | 客户端 → Nginx → 应用服务 → MySQL            |
| 在哪台机器上抓？       | 一般选问题两端之一，必要时两端同时抓以做对比 |
| 对端 IP 和端口是什么？ | 应用服务 10.0.0.5:8080，数据库 10.0.0.8:3306 |
| 问题是必现还是偶发？   | 偶发问题需要长时间抓包并做文件轮转           |
| 问题发生在什么时间？   | 用于在抓包文件中定位，并与日志对照           |

## 3.2 登录服务器，确认网卡

```bash
# 查看网卡与 IP
ip addr
# 或
ifconfig

# 查看 tcpdump 可用的接口
tcpdump -D

# 确认访问目标 IP 时走的是哪块网卡
ip route get 10.0.0.8
# 输出示例：10.0.0.8 dev eth0 src 10.0.0.5 ...

# 检查磁盘空间，选择空间充足的目录存放抓包文件
df -h
```

建议先用短时间的实时输出验证过滤条件是否正确：

```bash
tcpdump -i eth0 -nn -c 20 'host 10.0.0.8 and port 3306'
```

看到预期的流量后，再改为写入文件。

## 3.3 执行抓包

**场景 A：问题可立即复现，进行短时间抓包**

```bash
tcpdump -i eth0 -nn -s 0 'host 10.0.0.8 and port 3306' -w /tmp/mysql_$(date +%Y%m%d_%H%M%S).pcap
```

复现问题后按 `Ctrl + C` 停止抓包。

**场景 B：抓取固定数量的包**

```bash
tcpdump -i eth0 -nn -s 0 -c 50000 'port 8080' -w /tmp/app.pcap
```

**场景 C：偶发问题，需要后台长时间抓包并轮转文件（推荐）**

```bash
mkdir -p /data/capture
nohup tcpdump -i eth0 -nn -s 0 \
    'port 8080 and not port 22' \
    -C 200 -W 20 \
    -w /data/capture/app.pcap \
    -Z root > /data/capture/tcpdump.log 2>&1 &
# 记录进程号
echo $!
```

这条命令会生成 `app.pcap00`、`app.pcap01` 等最多 20 个文件，每个约 200MB，总共占用不超过约 4GB 磁盘，写满后循环覆盖最旧的文件。

也可以按时间轮转。下面的命令每 10 分钟生成一个文件，最多保留 144 个（即 24 小时）：

```bash
nohup tcpdump -i eth0 -nn -s 0 'port 8080' \
    -G 600 -W 144 \
    -w '/data/capture/app_%Y%m%d_%H%M%S.pcap' -Z root > /dev/null 2>&1 &
```

如果只关心协议头，不需要应用层内容时（如只分析 TCP 行为），可以使用 `-s 128` 之类的较小截取长度，文件体积能大幅缩小。

**场景 D：使用 timeout 控制抓包时长**

```bash
timeout 300 tcpdump -i eth0 -nn -s 0 port 443 -w /tmp/https.pcap   # 5 分钟后自动停止
```

复现问题，或者等待问题发生，同时记下发生的准确时间点，以及相关请求 ID、客户端 IP 等信息，然后停止抓包。

```bash
# 前台运行：按 Ctrl + C

# 后台运行：
ps -ef | grep tcpdump
kill <PID>        # 发送 SIGTERM 信号，tcpdump 会正常刷新缓冲区后退出
```

## 3.4 在本地使用 Wireshark 分析

先将 pcap 文件传输到本地，如果文件较大，可以先使用 tar 压缩再下载。

使用 Wireshark 打开单个 pcap 文件，或者选择合并多个轮转文件后再打开，然后进行分析。

## 3.5 实战案例

以下是几个实战案例：

#### 案例一：接口偶发超时，定位是网络问题还是服务端问题

**现象**：客户端 192.168.1.20 调用服务端 10.0.0.5:8080 的接口，偶尔在 3 秒后超时。

**抓包命令**（在服务端执行）：

```bash
nohup tcpdump -i eth0 -nn -s 0 'host 192.168.1.20 and port 8080' \
  -C 100 -W 10 -w /data/capture/api.pcap -Z root &
```

**分析过程**：

1. 在 Wireshark 中打开文件，查看"专家信息"，发现大量 `Retransmission`。
2. 应用显示过滤器 `tcp.flags.syn==1 && tcp.analysis.retransmission`，发现 SYN 包被重传，间隔约为 1 秒、2 秒……而且服务端始终没有回复 SYN+ACK。
3. 结论：问题发生在 TCP 握手阶段，而不是应用处理慢。可能原因包括：服务端半连接队列或全连接队列溢出，需要结合 `netstat -s | grep -i listen` 查看 overflow 计数；安全组或防火墙丢包；中间网络设备丢包。

如果握手正常，但使用 `http.time > 2` 过滤后发现请求发出很久之后服务端才回复响应，说明问题在**服务端应用处理慢**，应该转向排查应用日志和数据库慢查询。

#### 案例二：连接被莫名断开

1. 使用显示过滤器 `tcp.flags.reset == 1`，找出所有 RST 包。
2. 查看 RST 是由哪一方发出的，以及它之前的交互：
   - 连接长时间空闲后被 RST：通常是中间的负载均衡或防火墙会话超时，或者对端进程已关闭连接。
   - 发送数据时收到 RST：通常是对端已经关闭连接，或者端口没有监听。
3. 右键该包，选择"追踪 TCP 流"并结合流量图，查看完整的时序。

#### 案例三：传输速度慢

1. 打开 **统计 → TCP 流图形 → 窗口缩放**，观察接收窗口是否长期很小，或者是否出现 `Zero Window`，这说明接收方处理不过来。
2. 查看 **往返时间（RTT）** 图，判断网络延迟是否过高。
3. 查看 **Stevens 序列号图**，判断是否存在频繁重传。
4. 检查握手包中的 `wscale` 选项，确认窗口缩放是否生效。
